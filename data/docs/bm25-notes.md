# BM25 检索算法速记

## 一句话

BM25 是一种基于词频的排序函数，用来给「查询」和「文档」的相关性打分，是全文检索引擎
（Lucene、Elasticsearch 的默认相似度）的经典基线。

## 公式

对查询里的每个词项 q，把下面这一项在所有文档上累加：

```
score(D, Q) = Σ  IDF(q) · ( f(q,D) · (k1 + 1) ) / ( f(q,D) + k1 · (1 - b + b · |D| / avgdl) )
```

其中：

- `f(q,D)`：词项 q 在文档 D 中出现的次数（词频 TF）
- `|D|`：文档长度，`avgdl`：所有文档的平均长度
- `k1`：控制词频饱和速度，常用 1.2 ~ 2.0（本仓库取 1.5）
- `b`：控制长度归一化的强度，常用 0.75
- `IDF(q) = ln(1 + (N - n(q) + 0.5) / (n(q) + 0.5))`，N 是文档总数，n(q) 是包含 q 的文档数

## 为什么要 k1 和 b

- 一个词出现 10 次不应该比出现 5 次"相关 2 倍"，所以 `k1` 让词频收益递减（饱和）。
- 长文档天然容易命中更多词，所以用 `b` 按长度做惩罚，避免长文占便宜。

## 中文怎么办

BM25 本身只认 token，不认字。中文没有空格，通常要先分词。本项目的做法是
**字符 unigram + bigram**：把"梯度下降"切成 梯/度/下/降/梯度/度下/下降。
好处是不需要词典、对新词友好；代价是索引会大一些。

## 它和向量检索的区别

| 维度 | BM25 | 向量检索 |
|---|---|---|
| 匹配方式 | 字面匹配（词项重合） | 语义匹配（向量距离） |
| 强项 | 专有名词、编号、精确术语 | 同义改写、跨语言、模糊描述 |
| 弱项 | 换个说法就召回不到 | 精确编号容易漂移 |
| 成本 | 纯 CPU，毫秒级，零依赖 | 需要 embedding 模型 + 向量库 |

实践中常见做法是两者混检（hybrid search）再用 RRF 融合排名。
